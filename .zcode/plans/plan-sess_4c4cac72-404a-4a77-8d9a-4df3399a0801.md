## Phase 2 — Fix program correctness bugs (so gameplay actually works)

- **Fix `emergency_pause.rs`:** change seed `b"global_config"` → `b"global_config_v2"` (match all other modules).
- **Fix `buy_ticket.rs`:** enforce that `lottery_token_account` is the vault ATA / PDA that `claim_prize` expects (`[b"lottery_vault", lottery]` or the ATA-of-lottery-PDA — confirm against `claim_prize.rs` and make both sides consistent). Validate `usdc_mint` against `global_config.usdc_mint`.
- **Fix `initialize.rs`:** persist `global_config.bump = ctx.bumps.global_config`, set `created_at`/`updated_at`, set sensible validation limits (`min_ticket_price`, `max_draw_duration`, etc.).
- **Enforce `is_paused`:** add `require!(!global_config.is_paused, ...)` to `create_lottery` and `buy_ticket`.
- **Decide on dead-code files:** delete the 4 non-compiling disabled instruction files (`switchboard_vrf.rs`, `cancel_lottery.rs`, `claim_refund.rs`, `treasury.rs`) and their `mod.rs`/`lib.rs` references. They contradict active seeds and won't compile. We re-implement cancel+refund cleanly if needed; treasury fee already works via `claim_prize`'s fee-split CPI.
- **Verify:** `anchor build` still clean after fixes.

## Phase 5 — Frontend (Next.js + Phantom + USDC)

Scaffold a fresh Next.js (App Router) + Tailwind + shadcn/ui app in `frontend/`.

- **`lib/solana/`**: load generated IDL, Anchor `Program` provider, devnet RPC connection.
- **Wallet**: Phantom via `@solana/wallet-adapter-react` (auto-connect, disconnect, address display, SOL/USDC balance).
- **USDC helpers**: get-or-create associated token account, devnet mint constant.
- **Views:**
  - **Home / Active Lotteries** — list lottery accounts (fetch all `LotteryAccount`), show prize pool, ticket price, draw countdown, state badge.
  - **Buy Ticket** — connect → USDC balance check → approve + buy → ticket confirmation.
  - **My Tickets** — tickets owned by connected wallet + claim button when their lottery is Completed and they won.
  - **Claim Prize** — calls `claim_prize`, shows payout.
  - **Admin panel** (optional this phase) — create lottery, transition states, pause toggle.
- **`.env.local`**: `NEXT_PUBLIC_USDC_MINT`, `NEXT_PUBLIC_PROGRAM_ID`, `NEXT_PUBLIC_RPC_URL`.
- **Verify:** connect Phantom (devnet), buy a ticket with devnet USDC against the Phase-4 lottery, see it reflected on-chain.

## Phase 6 — Lightweight keeper + end-to-end demo

- **`scripts/keeper.ts`**: polls active lotteries; when `draw_time` passed and state is Open/Locked, sends `transition_state` → `settle_randomness` → `select_winner`. Runs via `npm run keeper`.
- **Full demo run:** create lottery → (frontend) buy tickets → (keeper) draw → (frontend) claim. All on devnet.
